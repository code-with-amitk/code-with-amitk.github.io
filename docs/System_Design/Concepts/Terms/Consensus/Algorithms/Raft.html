What is Raft? How it works

Raft(Strong Consistent System)

What is Raft?
- Raft is a consensus algorithm, where multiple nodes agree before commiting a value to system. Has same fault tolerance as Paxos
- Raft can be used writing content to DB. Leader & Followers agree to commit and then data is committed to DB.

Traditional Replication(Directly Written) Raft Protocol (Agree then Commit)
Write to DB Sequence DB executes on Leader ➔ streamed to Slaves. Written to Log ➔ Quorum Agreed ➔ Executed into DB.
Split-Brain Risk High. If the network splits, two nodes might think they are the leader and write conflicting data to disk. Zero. A network minority partition can never get a majority agreement, preventing conflicting writes.
Data Loss Risk of Loss. If the leader writes to its DB and crashes before sending it to replicas, that data is lost or trapped. No Loss. A write is only confirmed to the client if a majority safely saved the log.
Failover Orchestration Requires external orchestrators or human intervention to promote a new slave. Built-in & Instant. Nodes notice a missing leader and elect a new one in milliseconds automatically

How Raft works

Leader election — one node becomes Leader; others are Followers. There are no Slaves in Raft, its followers
Log replication — client writes Leader; Leader appends to its Raft log and sends log copies to Followers. Yet none, Leader or Follower writes to DB
Commit — Once majority (N/2+1) followers Acknowledge, Leader sends message to followers to commit into DB
Safety — if the Leader dies, a new election runs; committed entries are never lost.

Raft System Design

Requirements

Functional
1. Write into Raft logs(ie WAL log): System should accept commands from client, write in Raft logs before writing to DB
2. Leader Election:
3. Consensus: N/2 + 1 nodes to send ACK and then value is written to DB
4. Recovery: Master/Follower fails, system should recover
5. Serving Reads to clients
Non Functional
1. Fault Tolerance: Continue accepting writes until live nodes > N/2
2. Consistent: Nodes agree on committed value and system returns the same
