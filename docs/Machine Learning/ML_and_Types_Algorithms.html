1.1.1 Linear Regression = Linear Equation

linear regression finds the relationship between features(Given value = x) and a label(To be predicted value = y), ie finding the best-fit line
Linear equation in n variables is called 1 Neuron

Understand linear equation in Mathematics


y = mx + b    // x(Feature/Given value), y(Label/To be predicted value)
m(slope) = y2-y1 / x2-x1
         = 5-0 / 0 - 7 = -5/7

b is y intercept. ie point where line intersect y axis = 5

Equation: y = -5/7x + 5.
            = 7y + 5x = 35   //(0,5) (7,0) both satify the equation
In Machine Learning(Model with 1 feature(x))

y = wx + b
    w(weight), b(Bias)

In Machine Learning(Model with many features)

y = w1x1 + w2x2 + w3x3 ..+ b
    w(weight), b(Bias)

Types of Gradient Desent
1. Vanishing Gradients: During backpropagation, the gradients become extremely small, so the earlier layers of the neural network learn extremely slowly or almost stop learning. When the gradient values approach 0 for the lower layers, the gradients are said to "vanish". The ReLU activation function can help prevent vanishing gradients.
2. Exploding Gradients: During backpropagation, the gradients become extremely large. Batch normalization can help prevent exploding gradients

Hyperparameters

These are variables that control different aspects of training.
So m,b are parameters which need to be calculated during training, but hyperparameters define how m,b are derived
1. Learning rate: This determines magnitude of the changes to make to the weights and bias during each step of the gradient descent process for model to converge quickly. For example, if the gradient's magnitude is 2.5 and the learning rate is 0.01, then the model will change the parameter by 0.025.
  If the learning rate is too low, the model can take a long time to converge.
  if the learning rate is too high, the model never converges, but bounces around the weights and bias that minimize the loss.   Pick a learning rate that's not too high nor too low so that the model converges quickly.
2. Batch size: number of examples the model processes before updating its weights and bias
  a. Stochastic gradient descent(SGD): Uses single example (a batch size of one) per iteration to adjust m, b.
  b. Mini-batch stochastic gradient descent(mini-batch SGD): Compromise between full-batch and SGD.

1.1.2 Decision Tree

This is Binary Tree(not balanced) which works in flowchart-like manner where each internal node represents a "test" on an attribute, each branch represents the outcome of the test, and each leaf node represents numerical value (ie Prediction).
How it works? Predicting Whether a Customer Will Buy a Product Using Two Decision Trees
If Tree 1 predicts "Purchase" and Tree 2 predicts "No Purchase", the final prediction might be "Purchase" or "No Purchase" depending on the weight or confidence assigned to each tree.
Information Gain in Decision Tree
  Information Gain tells us how useful a question (or feature) is for splitting data into groups
  It measures how much the uncertainty decreases after the split.
  For example if we split a dataset of people into "Young" and "Old" based on age and all young people bought the product while all old people did not, the Information Gain would be high
Gini Index in Decision Tree: Metric to measure how often a randomly chosen element would be incorrectly identified. Lower Gini index represents a better split

Fitting
Overfitting in Decision Tree
when tree has too many splits becomes too deep, and it makes very good predictions to training data, but does poor predictions on new data.
As the tree gets deeper, the dataset gets sliced up into leaves with fewer choices. we'll have 210 groups by the time we get to the 10th level. That's 1024 leaves.
When we divide the tree in too many leaves, we also have fewer data in each leaf. Very few Leaves will make predictions that are quite close to actual values, but they may make very unreliable predictions for new data (because each prediction is based on only a few input samples).
Underfitting in Decision Tree
On otherside, if only few splits are performed(only 2 or 4), Resulting predictions may be far off for most input samples, even in the training data.
When a model fails to capture important distinctions and patterns in the data, & perform poorly even in training data, poorly in new data is underfitting
Overfitting or underfitting(What's preferred)? We need to hit a sweet spot between 2

Algorithms

1. KNN (K Nearest Neighbors). O(n)

Keyword search & Semantic Search is KNN algorithm for RAG pipeline's retriver. But KNN works in O(n) Complexity, ie it finds User's query embedding with 1:1 comparsion with log entries embeddings & will not scale if there are 1 billion entries. In this case we need to compare user query's embedding with all 1 billion log entries embedding.
And everytime there will be Billion comparisons.
Hence production retrievers use ANN

2. ANN(Approximate Nearest Neighbours)

ANN does not gurantee to find closest document to the query string, but can find very close by.

2.1 Navigable Small World (NSW)

How it works?
- Every document is represented by a embedding in embedding space
- It creates a GRAPH called PROXIMITY GRAPH, where every document's embedding is placed as 1 node
- Every node in graph is connected to its nearest neighbour
- When a user's query is received it embedding is calculated
- A RANDOM candidate node(on proximity graph) is choosen, now algorithm looks at closest neighbours of candidate node and find closesness to user's query embedding and finds which of them is closest to prompt vector
- Since there are very few neighbours to choose from, whichever is closest becomes the new candidate. Now process repeats for the new candidate
- Process continues until none of neighbours is closest to the current candidate and candidate vector is returned.
- With small modification this approach can return multiple closest vectors
- Proximity graph can be computed before recieving any user prompt

2.2 Hierarchial Navigable Small World (HNSW). O(logn)

How it works?
- It creates Hierarchail proximity graphs
- Layer-1 Proximity Graph: Contains all nodes on graph as created in Navigable Small World
- Layer-2 Proximity Graph: Randomly drop to only 100 vectors and build proximity graph for intermidiate navigation
- Layer-3 Proximity Graph: Randomly drop to just 10 vectors and build proximity graph
- Search begins in Layer-3. Algorithm chooses a RANDOM candidate in layer-3 graph and find searches closest to prompt(user query) vector
- Search goes to Layer-2 and finds best candidates in layer 2
- Search goes to Layer-3 and finds best candidates in layer 3
- HNSW is very fast wrt KNN

2. Cross-Encoder

Cross Encoder always provides better search results wrt Bi-Encoder, but it takes a bit of more time
How it work: Prompt is prepended to each Document before (Prompt+Document) is fed to special embedding model. Embedding model generates a relevancy score. Highest relevant score is taken as closest document(s).
Advantage:
  1. Quality of results is great and they can be used to improve results of other search techniques
Disadvantage:
  1. if there are billions of documents, there will be O(n) complexity as every document need to be passed with prompt to embedding model.
  2. Preprocessing(ie calculating the embeddings in advance before recieving the prompt) cannot be done, which can be done in Bi-Encoder

3. ColBERT(Contexualized Late Interaction over BERT)

Instead of generating 1 embedding vector for whole document(as in Cross-Encoder), ColBERT generate 1 embedding vector for 1 token
This process is carried for every document and also for prompt.
And then Each prompt vector is searched for most similar document vector
Advatanges:
  1. Provides scalability of Bi-encoder and high matching results of cross-encoder
  2. Faster than cross-encoder and can be used in real time searches
Disadvatanges:
  1. Number of vectors to be stored is very high wrt any other method

4. Reranking

Technique where Bi-encoder and cross-encoder are used in pipeline.
X Nearest documents are found to query vector using Bi-encoder
Then these X documents are fed to cross-encoder which further returns closest documents to the query.
if 1 billion documents are fed to Bi-encoder, 50-100 documents are outputted by Bi-encoder, which are fed to Cross-Encoder, which further finds nearest documents to Query. Cross-Encoder will return 10-15 documents.
